# Lumi Trades: an AI's public paper-trading crypto dashboard (paper trading only, not financial advice)

Live site: https://cypher-osiris.github.io/crypto-dashboard/ · X: [@lumisinsite](https://x.com/lumisinsite). "Lumi" is the AI persona that writes the analysis, the trade slate and the X drafts; the site says so openly.

Static site (plain HTML/CSS/JS, no build step) for GitHub Pages. Everything on the page is rendered by
`assets/app.js` from the JSON files in `data/`. Times display in US Central (America/Chicago).

### Coins: `data/coins.json` is the single list
Two groups, shown in this order everywhere (ticker, coin cards, signals, slate, calculator):
- **Lumi's Watchlist** (featured): `hedera-hashgraph` HBAR, `stellar` XLM, `ripple` XRP, `zebec-network` ZBCN,
  `axelar` AXL (**not** `axelar-network`).
- **Majors**: `bitcoin` BTC, `ethereum` ETH, `solana` SOL, `dogecoin` DOGE, `cardano` ADA, `chainlink` LINK, `sui` SUI.
BTC is a full coin and is also the Market backdrop (`"backdrop": "bitcoin"`). Verified 2026-10-21: every CoinGecko id
resolves to the right asset, and every `coinbase` product is online on Coinbase Exchange (websocket + candles). ZBCN
isn't on Coinbase, so it uses Kraken (`"kraken": "ZBCN/USD"`; REST pair `ZBCNUSD`).

To add or remove a coin, edit `data/coins.json` (`id`, `symbol`, `name`, `group`, `coinbase` *or* `kraken`, `colors`),
run `update_prices.py` and `signals.py`, then add a block under `coins` in `analysis.json` and an entry under
`slate.coins` in `trades.json`. Nothing else needs changing; the scripts read it through `scripts/coins.py`, and
the page reads it at load time. Coin charts below the fold are created lazily, and backtest data loads only near its
section. The browser's signals refresh is throttled to about 6 Coinbase requests per second.

## Each update (3× a day)

1. Run the data scripts (all stdlib, no keys):
   ```sh
   python3 scripts/update_prices.py   # ~15 s; prices.json, then track_trades.run() under the lock, auto log entry
   python3 scripts/signals.py --quiet # ~1 s; data/signals.json (use these readings when picking slate ideas)
   python3 scripts/context.py         # ~1 s; data/context.json
   ```
   `update_prices.py --no-fetch` re-evaluates trades without calling the API. `COINGECKO_DEMO_API_KEY` is optional.
   `signals.py` with no arguments prints the full JSON to stdout (for the 30-min alert job) and writes the file.
2. Edit `data/analysis.json`: bump `as_of` and `author`; update `commentary`, `bias`, `support`/`resistance`,
   `projection` (`horizon_days`, `bull`, `base`, `bear`) and `sources` (`[{title,url}]`, only things actually read).
   With 12 coins, prioritize the watchlist (full write-up every run). For majors, a short data-based update is fine
   (price, range, EMA/RSI from signals.json); `projection` is optional and the card hides it when absent. The majors
   were seeded Oct 21 with data-only commentary, levels = 7-/30-day lows/highs, and no projection; replace them with a
   real read on the first full review. Keep `coins.bitcoin` consistent with `backdrop`.
3. Update the **slate** (do it while holding the lock so the 30-min tracker can't interleave, e.g.
   `scripts/locked.sh python3 my_edit.py`, or keep edits quick and run `scripts/publish.sh` right after) in `data/trades.json` (rules: max one active pending/open idea per coin, max **6** total (`slate_max` in `data/coins.json`), long or
   short, "no setup" allowed; new trades are **3x**). Append new trades to `trades` and point `slate.coins[<coin id>]`
   at them; for a coin without a setup use `{"trade_id": null, "note": "why not"}`. Bump `slate.as_of`. Never edit
   generated fields of closed trades. `current_idea_id` is kept for backward compatibility. Review all 12 coins
   but only post real setups. The 7 majors start as "not reviewed yet" no-setup entries (Oct 21), and the page lists
   no-setup coins compactly under the active cards. New trade template:
   ```json
   {"id":"T005","coin":"stellar","direction":"long","leverage":3,
    "entry":0.18,"entry_zone":{"low":0.179,"high":0.181},"stop":0.174,"targets":[0.19,0.198],
    "opened_at":"2026-10-22T08:00:00-05:00","expiry":"2026-10-24T08:00:00-05:00","status":"pending",
    "missed_it":{"max_entry":0.183,"note":"furthest price still worth entering, and when to skip"},
    "missed_plan":{"type":"pullback","trigger":"Retest of 0.1835–0.185 holds: a 1h candle trades into it and closes at or above 0.1835",
      "trigger_rule":{"tf":"1h","kind":"retest_hold"},"entry_zone":{"low":0.1835,"high":0.185},"stop":0.1805,"target":0.19,
      "leverage":3,"size_note":"normal size","reasoning":"which levels make the retest real, and why R:R >= 1.5",
      "expiry":"2026-10-24T08:00:00-05:00"},
    "reasoning":"levels + signals behind it","source":"analysis run"}
   ```
   **Every new idea must carry a `missed_plan`** ("Missed it? Here's the move", see "Missed-it plans" below). Write it
   from real levels only, with R:R >= 1.5 from the WORST fill in its zone. If no such move exists, write
   `{"type":"none","reasoning":"no good chase; wait for a new setup: <why, with the levels>"}`. After editing, run
   `python3 scripts/track_trades.py` and check `slate_warnings` (it flags a missing plan, missing fields, R:R < 1.5,
   or a non-machine-checkable trigger).
   `status: "open"` = entered at `entry` immediately. `pending` fills when price trades into `entry_zone` (fill price
   replaces `entry`, the plan is kept in `planned_entry`) and becomes `cancelled` at `expiry` (legacy `fill_by` also
   works). Optional `expires` closes an open trade at market. Times without an offset are read as Central time.
   The update script prints a WARNING (and stores `stats.slate_warnings`) if the slate rules are broken.
4. Prepend an `{"t": ISO-UTC, "kind":"analysis", "author":"...", "text":"..."}` entry to `data/log.json`.
5. Refresh the social card: `python3 scripts/make_og.py` (rewrites `assets/og.png` from the current slate, ~1 s).
6. Publish: `PUBLISH_MSG="Evening update" scripts/publish.sh data index.html assets/og.png` (or the manual git steps below).

## Live data in the browser
Prices stream straight from exchanges to the visitor (nothing to run): Coinbase Exchange websocket `ticker` for
every `coinbase` product in data/coins.json; Kraken v2 websocket for ZBCN/USD (not listed on Coinbase); CoinGecko
`simple/price` every 60 s for any coin whose socket is down. Signals refresh every 3 min, market context every 5 min
(CoinGecko /global, alternative.me Fear & Greed, OKX public funding/open interest). If a source fails, the JSON
snapshot stays on screen. Binance/Bybit are not used (geo-blocked in the US).

## Trade tracking (scripts/track_trades.py)
Single engine used by the 30-min job and by `update_prices.py`. For each pending/open trade it pulls only the candles
**closed since that trade's `last_checked_ms`**: Coinbase Exchange 5m (1h if the gap is > 7 days; ZBCN via Kraken 5m,
60m if > 55 h; CoinGecko price points as the last fallback). Rules, candle by candle:
- **Fill:** a pending trade fills when a candle's range touches `entry_zone`. Fill price = the zone edge on the side
  the candle came from (the first edge price would touch, e.g. a long dropping into the zone fills at `high`), or
  the candle's open if it opened inside the zone. `filled_at` = candle start. The plan stays in `planned_entry`.
- In the fill candle only the **stop** is checked (we can't know whether a target came before the fill).
- **Stop vs target in one candle → stop** (conservative). Size split equally across targets; after T1 the stop moves to
  the fill price from the next candle on (`"move_stop_to_be": false` disables). All targets → **won**; partial then
  stop → **won** if blended P&L > 0 else **lost**. Pending past `expiry` (or legacy `fill_by`) → **cancelled**;
  optional `expires` closes an open trade at market.
- P&L % = price move × leverage, on margin, no fees/funding. Leverage: T001 was 5x; from Oct 21, 2026 new ideas are 3x.
- Every run sets `last_checked` (ISO) / `last_checked_ms` per trade and `tracked_utc`, so it is **idempotent**: a
  re-run never double-counts a candle. `data/log.json` gets an entry **only when an event happens**.
- Prints `{"checked_utc","events":[...],"publish":bool,"active":[...],"sources","errors","slate_warnings"}`.
  Event types: `filled`, `target1_hit`/`target2_hit`, `stopped`, `won`, `lost`, `cancelled`.
- Stats: win rate = won / closed; cumulative P&L = simple sum of closed trades' P&L %.

### Missed-it plans (`missed_plan` on a trade)
Backward compatible: trades without it work as before; `missed_it` (`max_entry` + note) stays and defines when the idea counts as missed.

| field | meaning |
|---|---|
| `type` | `pullback` (retest of a level after the run), `breakout` (close through a level), `flip` (opposite side after the idea is invalidated), `none` (no good chase) |
| `trigger` | the condition in words, e.g. "1h close above 1.42" or "retest of 1.38–1.385 holds" |
| `trigger_rule` | machine version: `{"tf":"1h","kind":"retest_hold"}` (uses `entry_zone`: long = 1h low <= zone.high and close >= zone.low; short mirrored), `{"tf":"1h","kind":"close_above","level":x}`, `{"tf":"1h","kind":"close_below","level":x}`. Pullback defaults to retest_hold. Without a rule the plan is shown but not auto-tracked (warning). |
| `entry_zone` `{low,high}`, `stop`, `target` | the plan trade (one target) |
| `leverage` | default 3; **2 for chase entries** |
| `size_note` | e.g. "half size: worse R:R" |
| `reasoning` | the level-based rationale (and, for `none`, why no chase works) |
| `expiry` | optional; default = the main idea's expiry |
| `direction` | optional; default = same as the idea (`flip` = opposite) |
| `status`, `armed_at`, `triggered_at`, `linked_id`, `ended_at`, `last_checked(_ms)` | written by the tracker; don't hand-edit |

Rules: a real level-based rationale and **R:R >= 1.5 from the worst fill** (long: zone.high, short: zone.low), else `type: none`.
Tracker (`track_trades.py`, every 30 min): `watching` → `armed` when the idea is still pending and a 5m close is past
`missed_it.max_entry`, or the idea expired unfilled (flip: when the idea is stopped, or a 1h close beyond its stop).
`armed` + trigger on a completed 1h candle → **linked trade `<id>b`** (`parent_id`, `plan_type`, `source: "missed_plan of <id>"`):
open at the trigger close if it is inside the plan zone, else pending in the zone until the plan expiry. A still-pending
main idea is cancelled with `cancel_reason: "superseded by missed-it plan"` and `slate.coins[coin].trade_id` moves to the
linked trade, so one idea per coin holds. The linked trade is then tracked like any other trade and counts in the record.
Other outcomes: `void` (the idea filled first), `invalidated` (1h close beyond the plan stop while armed), `expired`.
Every transition is a trade event (`missed_plan_armed` / `_triggered` / `_void` / `_invalidated` / `_expired`, plus
`cancelled` for the superseded idea), so the 30-min job publishes it and log.json records it. Plans that fail validation
are never auto-activated. Plan scanning starts at the first full hour after the plan was written (no back-dating).

The slate card shows a collapsible "Missed it?" block (trigger, zone, stop, target, leverage, R:R worst/best, size note,
live distance to the plan zone or trigger, and the reasoning). It highlights and opens itself while price is past the
missed-it limit or the plan is armed, unless the reader has toggled it.

### Locking
`track_trades.py`, `update_prices.py`, `publish.sh` and `locked.sh` all take an exclusive `flock` on `state/lock`
(git-ignored, waits up to 300 s, released automatically if a process dies), so the 30-min job and the 3×-daily job
never write `trades.json`/`log.json` or run git at the same time.

### The 30-minute job (exact commands)
```sh
cd crypto-dashboard
python3 scripts/signals.py --quiet
out=$(python3 scripts/track_trades.py); echo "$out"
echo "$out" | python3 -c 'import sys,json; sys.exit(0 if json.load(sys.stdin)["publish"] else 1)' \
  && PUBLISH_MSG="Trade events $(TZ=America/Chicago date '+%Y-%m-%d %H:%M %Z')" \
     scripts/publish.sh data/trades.json data/log.json data/signals.json
```
It publishes only when a trade event happened (otherwise `last_checked` churn would create a commit every 30 min);
the next 3×-daily publish picks up the quiet `last_checked` updates. `publish.sh` exit codes: 0 ok (or nothing to
commit), 1 git failure, 2 invalid JSON, 3 lock timeout.

## Signal backtest (scripts/backtest.py)
```sh
python3 scripts/backtest.py            # uses state/cache (12 h) ; --refresh re-downloads
```
History: Coinbase 1h for 365 days (4h resampled from it) and 1d for 730 days; ZBCN from Kraken (720 bars per
interval: ~30 days 1h, ~120 days 4h, ~2 years 1d). The per-bar indicator series are causal and verified against
`signals.analyze()` on random bars (`verify_max_score_diff`, must be 0). Measures every indicator event (transitions
into RSI ≤30/≥70, MACD crosses, EMA crosses/stacks, Bollinger breaks, StochRSI turns, volume spikes, squeezes,
timeframe score labels) and the composite labels on the 4h grid: forward 4h/24h/72h returns, hit rate vs. base
rate, edge, t-stat (ignores overlap, so optimistic). Strategy sim: enter at the next bar's open on a composite Strong
Buy/Sell, any composite Buy/Sell, a 4h MACD cross, or the daily score; 3x, 1.5×ATR stop, 3×ATR target, time stop,
0.06% fee per side, stop first on ambiguous 1h candles, fixed margin (no compounding), vs. 1x buy-and-hold. Weights:
information coefficient per component, first 70% in-sample / last 30% out-of-sample; candidate weightings are only
**proposed** in `backtest.json`. A weighted score is added to `signals.py` only if a weighting reaches OOS mean IC
≥ 0.02 and is positive in ≥ 70% of series. On the Oct 21, 2026 run it was not, so there is no `--weighted` flag and no
`data/signal_weights.json`. The dashboard keeps equal weights. Re-run it weekly or so and commit `data/backtest.json`.

## Affiliate link (data/config.json)
```json
{ "affiliate": { "bitunix_url": "https://…your referral link…", "label": "Trade on Bitunix",
                "coinbase_url": "", "coinbase_label": "Trade on Coinbase" } }
```
**Geo-gated (assets/affiliate.js).** Bitunix bans US users, so Bitunix links are shown only to visitors confirmed
NON-US; US visitors (incl. PR/GU/VI/AS/MP/UM) get the Coinbase slot instead, which shows nothing while `coinbase_url`
is empty. Country lookup, client-side: `https://api.country.is/` → `https://ipapi.co/country/` (2.5 s timeout each) →
`Intl` time zone (US zones such as America/New_York, Chicago, Denver, Los_Angeles, Phoenix, Anchorage, Detroit, Boise,
Indiana/*, Kentucky/*, Pacific/Honolulu ⇒ US). The result is cached in `sessionStorage` (`lumi_geo_v1`). Fail closed:
everything stays hidden until the country is known, and if it can't be determined nothing is shown. Debug override:
`?geo=US` / `?geo=DE` (not cached). `<html data-geo="us|non-us|unknown">` shows the decision.
X posts (`make_post.py`) can't be geo-gated: keep Bitunix links out of posts aimed at a US audience.

When `bitunix_url` is a non-empty `https://` URL the site shows a "Trade this setup on Bitunix" button on every
active (pending/open) slate card, a button in the position calculator and a small CTA in the header. Every link has
`rel="sponsored noopener" target="_blank"`. The disclosure ("Some links are affiliate links; we may earn a commission
at no cost to you. Paper trades, not financial advice.") appears under each button and in the footer. Set it to `""`
to hide all of it, including the disclosure. Edit, commit and push: no `?v=` bump is needed, because the config is
fetched without the cache. The URL is HTML-escaped when rendered (`&` → `&amp;`), so paste it exactly as given.

## X posts (scripts/make_post.py + docs/x_voice.md)
`make_post.py` is a **data helper**. It supplies facts, checks numbers and draws the card; the post text is written with
judgment following `docs/x_voice.md` (the Lumi voice, formats, rules and examples).
```sh
python3 scripts/make_post.py facts --pretty   # compact JSON: slate (+distance to zone), changes since last post, trade events,
                                              # movers, BTC levels, record, 1-2 sourced catalysts, sentiment, links
python3 scripts/make_post.py check post.txt   # every number must exist in the data at the precision written; X lengths
python3 scripts/make_post.py save post.txt --kind midday --focus XRP   # posts/YYYY-MM-DD-HHMM.txt + .png, sets the baseline
python3 scripts/make_post.py card --focus slate --out /tmp/card.png    # 1200x675 "Lumi Trades" card only
```
Thread replies go in the same file, separated by a line containing only `---`. News comes from optional `catalysts`
arrays in `analysis.json` (`{date, kind: news|event, text, source, url}`, only items actually read). The card has a
focal coin (big symbol and price, a 7-day line, the zone, stop and T1) or `--focus slate`. Brand and URL are small.
It needs matplotlib, plus fontTools for the bold weights, which are cached in `state/fonts`. Nothing is ever posted
automatically.
