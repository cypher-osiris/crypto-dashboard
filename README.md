# Crypto Dashboard (paper trading only — not financial advice)

Static site (plain HTML/CSS/JS, no build step) for GitHub Pages. Everything on the page is rendered by
`assets/app.js` from the JSON files in `data/`. Times display in US Central (America/Chicago).

```
index.html            page shell (Chart.js 4 + chartjs-plugin-annotation 3 from jsDelivr; Inter + JetBrains Mono from Google Fonts)
assets/style.css      dark, mobile-friendly theme
assets/app.js         renders all sections from data/*.json (ticker, cards, charts, trades, log)
assets/live.js        live prices in the browser: Coinbase websocket (BTC/XRP/XLM/HBAR/AXL), Kraken websocket (ZBCN),
                      CoinGecko 60s polling fallback; auto-reconnect + watchdog; LIVE/DELAYED/SNAPSHOT indicator
assets/signals.js     in-browser signals (Coinbase/Kraken candles, CoinGecko fallback), same math as scripts/signals.py
assets/extras.js      market-context strip, track record ($100 margin/trade), position calculator
assets/backtest.js    "Signal Backtest" section (renders data/backtest.json)
assets/markets.js     Global Markets panel: live TSE/HKEX/LSE/NYSE session clocks + 24h timeline (Intl/IANA, DST-safe; no holidays)
data/prices.json      GENERATED  – quotes + 30-day ~hourly history (CoinGecko)
data/trades.json      HAND-EDITED ideas + GENERATED status/P&L/stats
data/analysis.json    HAND-EDITED commentary, support/resistance, bull/base/bear projections
data/signals.json     GENERATED by scripts/signals.py (snapshot shown until the browser computes its own)
data/context.json     GENERATED by scripts/context.py (fallback for the live context strip)
data/backtest.json    GENERATED by scripts/backtest.py (signal backtest; ~240 KB)
data/log.json         update log (scripts prepend "auto" entries; analysis runs add "analysis" entries)
scripts/update_prices.py   fetch prices, then delegate trade evaluation to track_trades.py (Python 3.9+, stdlib only)
scripts/track_trades.py    THE trade engine: fills/stops/targets/expiry from 5m candles; run every 30 min (~1 s, no args)
scripts/publish.sh         pull --rebase --autostash, validate JSON, commit data if changed, push (no prompts)
scripts/locked.sh          run any command while holding state/lock (use for hand edits of trades.json/log.json)
scripts/backtest.py        backtest of the signals.py indicators/composite -> data/backtest.json (~20 s first run)
scripts/signals.py         RSI/MACD/EMA/Bollinger/StochRSI/volume signals -> data/signals.json + JSON on stdout (~1 s, no args)
scripts/context.py         total mcap, BTC dominance, Fear & Greed, OKX BTC funding/OI -> data/context.json
```

Coins (CoinGecko IDs, verified 2026-10-21): `hedera-hashgraph` HBAR, `stellar` XLM, `ripple` XRP,
`zebec-network` ZBCN, `axelar` AXL (**not** `axelar-network`), plus `bitcoin` as the backdrop.
To change coins edit `COINS` in the script and add a matching block under `coins` in `analysis.json`.

## Each update (3× a day)

1. Run the data scripts (all stdlib, no keys):
   ```sh
   python3 scripts/update_prices.py   # ~15 s; prices.json, then track_trades.run() under the lock, auto log entry
   python3 scripts/signals.py --quiet # ~1 s; data/signals.json (use these readings when picking slate ideas)
   python3 scripts/context.py         # ~1 s; data/context.json
   ```
   `update_prices.py --no-fetch` re-evaluates trades without calling the API. `COINGECKO_DEMO_API_KEY` is optional.
   `signals.py` with no arguments prints the full JSON to stdout (for the 30-min alert job) and writes the file.
2. Edit `data/analysis.json`: bump `as_of` and `author`; update `commentary`, `bias`, `support`/`resistance`,
   `projection` (`horizon_days`, `bull`, `base`, `bear`) and `sources` (`[{title,url}]`, only things actually read).
3. Update the **slate** (do it while holding the lock so the 30-min tracker can't interleave, e.g.
   `scripts/locked.sh python3 my_edit.py`, or keep edits quick and run `scripts/publish.sh` right after) in `data/trades.json` (rules: max one active pending/open idea per coin, max 5 total, long or
   short, "no setup" allowed; new trades are **3x**). Append new trades to `trades` and point `slate.coins[<coin id>]`
   at them; for a coin without a setup use `{"trade_id": null, "note": "why not"}`. Bump `slate.as_of`. Never edit
   generated fields of closed trades. `current_idea_id` is kept for backward compatibility. New trade template:
   ```json
   {"id":"T005","coin":"stellar","direction":"long","leverage":3,
    "entry":0.18,"entry_zone":{"low":0.179,"high":0.181},"stop":0.174,"targets":[0.19,0.198],
    "opened_at":"2026-10-22T08:00:00-05:00","expiry":"2026-10-24T08:00:00-05:00","status":"pending",
    "missed_it":{"max_entry":0.183,"note":"furthest price still worth entering, and when to skip"},
    "reasoning":"levels + signals behind it","source":"analysis run"}
   ```
   `status: "open"` = entered at `entry` immediately. `pending` fills when price trades into `entry_zone` (fill price
   replaces `entry`, the plan is kept in `planned_entry`) and becomes `cancelled` at `expiry` (legacy `fill_by` also
   works). Optional `expires` closes an open trade at market. Times without an offset are read as Central time.
   The update script prints a WARNING (and stores `stats.slate_warnings`) if the slate rules are broken.
4. Prepend an `{"t": ISO-UTC, "kind":"analysis", "author":"...", "text":"..."}` entry to `data/log.json`.
5. Publish: `PUBLISH_MSG="Evening update" scripts/publish.sh data index.html` (or the manual git steps below).

## Live data in the browser
Prices stream straight from exchanges to the visitor (nothing to run): Coinbase Exchange websocket `ticker` for
BTC-USD, XRP-USD, XLM-USD, HBAR-USD, AXL-USD; Kraken v2 websocket for ZBCN/USD (not listed on Coinbase); CoinGecko
`simple/price` every 60 s for any coin whose socket is down. Signals refresh every 3 min, market context every 5 min
(CoinGecko /global, alternative.me Fear & Greed, OKX public funding/open interest). If a source fails, the JSON
snapshot stays on screen. Binance/Bybit are not used (geo-blocked in the US).

## Trade tracking (scripts/track_trades.py)
Single engine used by the 30-min job and by `update_prices.py`. For each pending/open trade it pulls only the candles
**closed since that trade's `last_checked_ms`**: Coinbase Exchange 5m (1h if the gap is > 7 days; ZBCN via Kraken 5m,
60m if > 55 h; CoinGecko price points as the last fallback). Rules, candle by candle:
- **Fill:** a pending trade fills when a candle's range touches `entry_zone`. Fill price = the zone edge on the side
  the candle came from (the first edge price would touch, e.g. a long dropping into the zone fills at `high`), or
  the candle's open if it opened inside the zone. `filled_at` = candle start. The plan stays in `planned_entry`.
- In the fill candle only the **stop** is checked (we can't know whether a target came before the fill).
- **Stop vs target in one candle → stop** (conservative). Size split equally across targets; after T1 the stop moves to
  the fill price from the next candle on (`"move_stop_to_be": false` disables). All targets → **won**; partial then
  stop → **won** if blended P&L > 0 else **lost**. Pending past `expiry` (or legacy `fill_by`) → **cancelled**;
  optional `expires` closes an open trade at market.
- P&L % = price move × leverage, on margin, no fees/funding. Leverage: T001 was 5x; from Oct 21, 2026 new ideas are 3x.
- Every run sets `last_checked` (ISO) / `last_checked_ms` per trade and `tracked_utc`, so it is **idempotent**: a
  re-run never double-counts a candle. `data/log.json` gets an entry **only when an event happens**.
- Prints `{"checked_utc","events":[...],"publish":bool,"active":[...],"sources","errors","slate_warnings"}`.
  Event types: `filled`, `target1_hit`/`target2_hit`, `stopped`, `won`, `lost`, `cancelled`.
- Stats: win rate = won / closed; cumulative P&L = simple sum of closed trades' P&L %.

### Locking
`track_trades.py`, `update_prices.py`, `publish.sh` and `locked.sh` all take an exclusive `flock` on `state/lock`
(git-ignored, waits up to 300 s, released automatically if a process dies), so the 30-min job and the 3×-daily job
never write `trades.json`/`log.json` or run git at the same time.

### The 30-minute job (exact commands)
```sh
cd /workspace/crypto-site
python3 scripts/signals.py --quiet
out=$(python3 scripts/track_trades.py); echo "$out"
echo "$out" | python3 -c 'import sys,json; sys.exit(0 if json.load(sys.stdin)["publish"] else 1)' \
  && PUBLISH_MSG="Trade events $(TZ=America/Chicago date '+%Y-%m-%d %H:%M %Z')" \
     scripts/publish.sh data/trades.json data/log.json data/signals.json
```
It publishes only when a trade event happened (otherwise `last_checked` churn would create a commit every 30 min);
the next 3×-daily publish picks up the quiet `last_checked` updates. `publish.sh` exit codes: 0 ok (or nothing to
commit), 1 git failure, 2 invalid JSON, 3 lock timeout.

## Signal backtest (scripts/backtest.py)
```sh
python3 scripts/backtest.py            # uses state/cache (12 h) ; --refresh re-downloads
```
History: Coinbase 1h for 365 days (4h resampled from it) and 1d for 730 days; ZBCN from Kraken (720 bars per
interval: ~30 days 1h, ~120 days 4h, ~2 years 1d). The per-bar indicator series are causal and verified against
`signals.analyze()` on random bars (`verify_max_score_diff`, must be 0). Measures every indicator event (transitions
into RSI ≤30/≥70, MACD crosses, EMA crosses/stacks, Bollinger breaks, StochRSI turns, volume spikes, squeezes,
timeframe score labels) and the composite labels on the 4h grid: forward 4h/24h/72h returns, hit rate vs. base
rate, edge, t-stat (ignores overlap, so optimistic). Strategy sim: enter at the next bar's open on a composite Strong
Buy/Sell, any composite Buy/Sell, a 4h MACD cross, or the daily score; 3x, 1.5×ATR stop, 3×ATR target, time stop,
0.06% fee per side, stop first on ambiguous 1h candles, fixed margin (no compounding), vs. 1x buy-and-hold. Weights:
information coefficient per component, first 70% in-sample / last 30% out-of-sample; candidate weightings are only
**proposed** in `backtest.json`. A weighted score is added to `signals.py` only if a weighting reaches OOS mean IC
≥ 0.02 and is positive in ≥ 70% of series. On the Oct 21, 2026 run it was not, so there is no `--weighted` flag and no
`data/signal_weights.json`. The dashboard keeps equal weights. Re-run it weekly or so and commit `data/backtest.json`.

## Publishing (GitHub Pages)
Live site: https://cypher-osiris.github.io/crypto-dashboard/ · repo: https://github.com/cypher-osiris/crypto-dashboard
(Pages builds from `main`, folder `/`; `.nojekyll` disables Jekyll processing.)

```sh
cd /workspace/crypto-site
python3 scripts/update_prices.py        # then hand-edit analysis/trades/log as needed
scripts/publish.sh data                 # scripted: lock, pull --rebase --autostash, validate, commit if changed, push
# or manually:
git add -A
git commit -m "Update $(TZ=America/Chicago date '+%Y-%m-%d %H:%M %Z')"
git push                                # non-interactive via gh credential helper (gh auth setup-git)
```
Data-only updates need nothing else (JSON is fetched with a cache-busting query). If you change CSS/JS, bump the
`?v=` version (currently `20261021-4`) on the asset links in `index.html` so browsers pick up the new files.
A Pages rebuild usually takes under a minute; check with
`gh api repos/cypher-osiris/crypto-dashboard/pages/builds/latest --jq .status`.
Never commit API keys: pass `COINGECKO_DEMO_API_KEY` via the environment only (`.env*` is git-ignored).
